# Offline B2B normal Factur-X PDF prototype

Reference commit: `0d27f50`. No Bridge production file or validated CII module is
modified. No deployment, payment, webhook, Airtable or network operation.

## Namespace decision, based on the supplied official package

Archive: `Factur-X-1.09.2-Zugferd-2.5.2-2026-08-04-FINAL-FR.zip`.
Guide `1. FACTUR-X 1.09.2 FR.pdf`, section 6.3.1, printed pages 32 and 33:
the namespace table AND both XML examples use
`urn:factur-x:pdfa:CrossIndustryDocument:invoice:1p0#`.
The supplied `2. FACTUR-X_extension_schema_exemple.xmp.txt` uses this same URI
both for fx and for pdfaSchema:namespaceURI. It is copied unchanged into assets.

The hybrid-rules appendix (PDF page 161), BR-HYBRID-04, omits `:invoice:`.
This is a real internal inconsistency, confirmed in the rendered page, not a
text-extraction accident. The prototype follows the dedicated schema definition
and its provided executable XMP example. This does NOT claim that FNFE/FeRD has
published an erratum for BR-HYBRID-04. No second/conflicting namespace is emitted.
Provenance and source hashes are recorded in assets/provenance.json.

## Architecture and scope

- inputs.py: reads the original expected.invoice.json and the existing explicit
  French fixture overlay through the unchanged CII module. Checks that these
  data reproduce the exact existing XML, but embeds only the original XML bytes.
  Checks historical validation hashes and preserved EN16931/BR-FR SVRL reports.
- render.py: local ReportLab renderer. Uses the explicit invoice and French notes;
  no numeric recomputation, remote logo, CSS, font or other remote resource.
  Every textual leaf of the prototype XML is covered by a readable-content test.
- assemble.py: PDF 1.7, document-level AF plus EmbeddedFiles name tree referencing
  the SAME Filespec; F/UF factur-x.xml, text/xml, Alternative, Params/ModDate,
  Size and checksum. Embeds both fonts and an RGB output intent, no encryption.
- xmp.py: instantiates the supplied official XMP and preserves its extension
  declaration; sets INVOICE, factur-x.xml, 1.0, EN 16931, pdfaid:part=3 and B.
  Actual document metadata replace all supplier/date/tool example placeholders.
- validate.py: structural inspection plus independent veraPDF execution.
- cli.py: stores a PDF and a validation report; returns 2 if conformity is blocked
  or fails. Structural PASS never becomes a PDF/A conformity claim.

Only PDF/A-3b is implemented. The renderer is separate from assembly; 3a can later
use a tagged renderer, logical structure and accessibility checks. Requesting 3a
now explicitly fails; it never just changes the XMP conformance letter.

Fonts: Bitstream Vera Regular and Bold from ReportLab 4.4.9, license included.
sRGB.icc is generated by Pillow/LittleCMS createProfile('sRGB') and pinned as a
local asset. All output uses RGB/gray, no images. Its PDF/A acceptability, like
that of the whole PDF, must be established by veraPDF.

The source fixture contains historical placeholder company/address information
and a generic PMD clause. They are preserved without alteration; this is not an
invoice to publish or a validated commercial policy for a real seller.

## Local commands (repository root jessie_bot)

Use a separate Python environment. Dependency installation is the only network
step; tests, generation and veraPDF validation run offline after installation.

```powershell
Set-Location -LiteralPath 'C:\Users\epicn\Desktop\NOVA PULSE_fr\Code\jessie_bot'
py -3.12 -m venv .venv-facturx-pdf
& .\.venv-facturx-pdf\Scripts\python.exe -m pip install -r .\requirements-facturx-pdf.txt
& .\.venv-facturx-pdf\Scripts\python.exe -B -m unittest discover -s .\tests\facturx_pdf -v
& .\.venv-facturx-pdf\Scripts\python.exe -B -m unittest discover -s .\tests\facturx -v
npm --prefix .\Bridge run test:billing:historical
$prototypeOut = Join-Path 'work' ('facturx-pdf-' + [guid]::NewGuid().ToString('N'))
$veraPdfExe = (Get-Command verapdf.bat -ErrorAction Stop).Source
& .\.venv-facturx-pdf\Scripts\python.exe -B -m billing_facturx_pdf.cli --out $prototypeOut --verapdf $veraPdfExe
Get-Content -LiteralPath (Join-Path $prototypeOut 'validation.json')
```

veraPDF and a compatible Java runtime must be installed locally; its launcher
must be on PATH for the commands above. No validator or Java runtime is bundled.
The CLI reads the actual veraPDF XML report, not just the process return code.

To validate an already generated prototype directly, use the separate script:

```powershell
& .\tests\facturx_pdf\validate-local.ps1 -PdfPath (Join-Path $prototypeOut 'NP-2026-000008-factur-x.pdf') -ReportPath (Join-Path $prototypeOut 'verapdf-direct.xml')
```

## Three B2B scenarios (normal, deposit, balance)

The PDF layer now supports --scenario b2b-normal, b2b-deposit or b2b-balance.
The default remains b2b-normal, retaining its existing fixture locations and API.
Deposit/balance exact validated XML and reports are in tests/facturx_pdf/fixtures/
b2b-deposit and b2b-balance. load_inputs derives the matching French overlay from
the invoice type; B2C and cross-scenario input/XML combinations explicitly fail.

Output filename is <invoice_number>-factur-x.pdf. Invoice titles distinguish
normal (380), deposit (386), balance (380). Existing quote and preceding deposit
references are shown, including the deposit date. All monetary values are copied;
the previous deposit is never deducted again from the balance totals.
The CII module, original historical fixtures, attachment and XMP code are unchanged.

Run from jessie_bot, using your configured Python environment:

    python -B -m unittest discover -s tests/facturx_pdf -v
    python -B -m billing_facturx_pdf.cli --scenario b2b-normal --out work/pdf-normal --verapdf C:\Users\epicn\verapdf\verapdf.bat
    python -B -m billing_facturx_pdf.cli --scenario b2b-deposit --out work/pdf-deposit --verapdf C:\Users\epicn\verapdf\verapdf.bat
    python -B -m billing_facturx_pdf.cli --scenario b2b-balance --out work/pdf-balance --verapdf C:\Users\epicn\verapdf\verapdf.bat

Each output directory must be new. The CLI retains validation.json alongside the
PDF. B2B acceptance still requires current CII validation AND veraPDF PASS.
In this Codex run: PDF tests 23 PASS / 0 FAIL / 1 BLOCKED-SKIP (SaxonC unavailable),
CII tests 15 PASS, historical tests 21 PASS. All three internal PDF structural
checks and XSD pass. Java is not accessible here, so veraPDF cannot execute:
PDF/A conformance remains BLOCKED / NOT ATTESTED for these newly generated PDFs.
